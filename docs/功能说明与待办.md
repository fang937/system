## 一、已实现功能

### 1. 账号与权限
- **四类角色**：学生（STUDENT）、实训讲师（TUTOR）、实训室负责人（LAB_ADMIN）、系统管理员（SYS_ADMIN），共用 `users` 表。
- **三入口登录**：学生端 / 导师端 / 管理员端，账号与入口强绑定，走错入口返回 403；JWT 鉴权。
- **合并工作台**：导师与实训室负责人同走导师端，登录返回 `caps`，负责人多一组「实训室事务」菜单（排期、室内调剂）。
- **职位管理**：管理员可在「导师与实训室」页查看每位成员职位（实训室负责人 / 实训讲师），一键调整：
  - 设为负责人时**自动撤销该室原负责人**（原子换防，无需先手动取消）；
  - 设为讲师时若本人是负责人，清空 `leader_id` 并提示该室进入无负责人状态；
  - 仅系统管理员有权调整，学生 / 导师调用返回 403。

### 2. 双选核心流程（8 阶段 · 三轮录取）
- `selection_phases` 一张表承载全部阶段行，时间窗口是唯一权威，所有写接口第一步校验时间，抓包直调同样被拒。
- **阶段序号严格对齐学院流程图**：1 宣讲 → 2 开放日 → 3 意向填报 → 4 面试与初选 → 5 拟录取确认 → 6 分轮录取 → 7 统筹调剂 → 8 结果公示。同一环节跨轮次共用同一个序号，即三轮填报都是 `seq=3`、三轮面试都是 `4`、三轮录取都是 `6`。
- **三轮录取**：第 6 阶段按轮次拆成「第一轮录取 / 第二轮录取 / 第三轮录取」三条（`code=SUPPLEMENT` + `round_no` 1~3），管理端以可折叠卡片呈现，卡片内是该轮的「面试与初选 + 拟录取确认」，志愿填报单独成段排在上方。
  - 录取窗口 = 本轮「面试与初选 → 拟录取确认」两段的包络：改录取时间会带动两段按原比例缩放；改两段越界时窗口自动扩展。志愿填报不纳入录取窗口。
  - 「立即进入」某个录取批次会把该轮面试与确认整体平移到当前，并同步切换当前轮次。
- **跨轮次界定范围**：已经持有待确认拟录取（`offer_status=1 AND confirm_status=0`）或递补（`offer_status=2`）的学生，不能再进入下一轮填报，也不会出现在全院 / 室内调剂池；已确认录取的由 `final_tutor_id` 拦截。避免一人占两个位置。
- **室内调剂的开放时间**：每轮「面试与初选」阶段即可执行实训室内调剂（室管工作台的「室内调剂」与管理员「统筹调剂」页的「执行实训室内调剂」同时开放）；全院跨室调剂与人工兜底仍只在「统筹调剂」阶段开放。
- 管理端可「立即进入 / 立即结束」平移窗口，方便演示。
- **意向填报**：学生最多 3 个平行志愿 + 服从实训室内调剂 / 全院调剂两个开关。
- **面试打分**：五维评分标准（专业基础 25% / 实践技能 25% / 学习潜力 20% / 动机匹配 15% / 表达沟通 15%），维度与权重落在 `score_rubrics` 表，前端与 AI 都以它为准。
- **名额并发控制**：`tutors.remaining_quota` + 乐观锁，拟录取用条件 UPDATE 防超卖；第 N+1 人点拟录取会被拒绝。
- **拟录取确认**：单 Offer 自动确认；多 Offer 学生限时选一；超时定时任务释放名额并按递补顺位自动递补。
- **统筹调剂**：三级兜底——实训室内 → 全院 → 人工约谈，按优先级分数从高到低匹配。
  - **不服从调剂的学生不自动分配**：`accept_lab_adjust` 与 `accept_global_adjust` 都为 0 时，自动调剂显式跳过，只计入 `manualPending` 并留在调剂池，等管理员在「人工分配」里约谈指定；管理端表格用「需人工 / 可自动」标签区分，统计卡单独显示「需人工处理」人数。
- **结果公示与导出**：POI 导出录取名单 Excel。

### 3. AI 能力（多通道）
- 三通道：OpenAI / DeepSeek / 通义千问，按优先级尝试，某通道额度耗尽自动切下一个；Key 全空时走内置规则引擎兜底。
- 学生端：面试 tips、实训室推荐（按技能标签 + 名额 + 竞争度）。
- 学生端：**AI 优化简历**（结构化草稿逐栏改写）与 **AI 面试辅导**（出题-作答-反馈），详见第 11 节。
- 导师端：教师 AI 分身（学生考察期咨询），身份资料与应答边界落在 `ai_personas` 表。
- **教师端 AI 辅助打分**：面试评分弹窗内「AI 简历初评」按五维评分标准（`score_rubrics`）给出各维度建议分 + 依据 + 把握程度，点「采用建议分」预填滑杆；AI 只出建议，最终仍由导师确认保存。
- **前置条件（未上传简历不可初评）**：学生必须有 `student_resumes` 记录。未上传时名单标「简历未上传」，「生成初评」禁用并给黄色说明，后端 `POST /api/ai/resume-review` 直接返回 400；**手工打分与处置不受影响**。已上传但加密/扫描件解析失败仍可初评，结果标注正文不可用并提示人工核对。AI 面试辅导、实训室推荐、分身问答不依赖简历，不受此限制。

### 4. 简历 OCR 与技能标签
- 仅对**已上传**的简历做解析；未上传时 AI 初评在解析前即被拦截（400），不产生任何 OCR 调用。
- PDF 优先抽文本层；扫描件调 PaddleOCR / PP-StructureV3 文档解析；DOCX 用 POI 直读段落与表格。
- 抽取结果缓存于 `resume_texts`，重新上传即失效。
- **简历技能标签**（`ResumeTagService`）：按 8 类词表（编程语言 / 后端框架 / 前端技术 / 数据库 / 中间件与部署 / AI 与数据 / 移动端 / 工程能力）从简历正文抽取技术标签。
  - 长词优先且命中区间不重叠，`Spring Boot` 不会同时产出 `Spring`；兼容 `SpringBoot`、`SpringCloud` 这类无空格写法。
  - 学生端「我的简历」上传后直接显示标签云与正文字数；教师端「AI 简历初评」在摘要下方展示同一套标签（`resumeTags`），不依赖大模型，模型不可用时照样出标签。

### 5. 实训室信息展示
- `labs` 表除核心方向外，承载 8 个实训室级横向对比字段：后端/工程技术栈、前端/客户端技术栈、AI/大模型方向、项目产出类型、竞赛/科研成果、培养模式、考核/结业标准、适合人群。
- 学生端导师页顶部「实训室概览」卡片组，可展开每室详情；管理端实训室编辑弹窗可改这 8 项。
- 真实名册幂等种子 `backend/src/main/resources/db/labs-tutors-seed.sql`，每次启动自动对齐，不重置已消耗名额、不改导师密码。

### 6. 其他
- 站内通知（Offer / 超时 / 结果）、操作日志、面试排期、学生档案与简历管理。
- 容器化：`docker-compose.yml`（mysql + backend + frontend/nginx），配置全部走 `.env`。

### 7. 师生直连私信
- 学生可在任意导师卡片打开抽屉，在「AI 分身」之外切换「直接留言」，**与全部 25 位导师真实对话**；导师端「学生留言」页统一收发，带未读红点。
- 私信页左侧为微信式两级选择：**最近会话** + **按实训室找老师**。先选实训室（手风琴，一次只展开一个），再点该室具体老师；未聊过的老师也能直接发起会话，对话区给「还没有和 XX 老师聊过」占位提示。
- 新表 `direct_messages`，与 `notifications` 分工：通知是系统单向广播，私信是双向会话 + 已读语义。
- 发送者永远取自登录身份（请求体不接受 senderId，杜绝冒名）；仅学生 ↔ 导师/负责人互通，学生↔学生、导师↔导师、自发均返回 400。

### 8. 双选时间轴（三端同步）
- 组件 `SelectionTimeline`，数据源为 `/api/meta/phase` 返回的 `phases`，与 `selection_phases` 同源，管理端改时间后三端立即一致。
- 8 步文案按学院流程图落地：集中宣讲 → 实训室开放日 → 意向填报 → 导师初选与面试考核 → 拟录取与学生确认 → 分轮录取（第一/二/三轮）→ 统筹调剂录取 → 结果公示与正式入组。
- 三个使用位置：
  - **管理端「阶段与轮次」**：完整版，每步带说明文字与倒计时，配合下方列表改时间 / 立即进入 / 立即结束；
  - **学生端「导师与方向」「我的志愿」**：紧凑版，8 步常显、说明可展开，填报窗口关闭后学生一眼看到已截止；
  - **教师端「报考我的学生」**：紧凑版，与管理员端同一份数据。
- 顶栏常驻阶段条：进行中为绿青渐变实色底 + 呼吸圆点 + 剩余时间胶囊，未开始为奶油底，无进行中阶段为灰底。阶段时间窗重叠时，一次列出全部进行中阶段及各自剩余时间（如「宣讲 剩余 02:19 | 开放日 剩余 00:36」）；**任一时间剩余不足 1 小时，该倒计时转为白底红字并加警示图标**，便于临期提醒；窄屏内容超宽时整条可横向滑动，右缘淡出提示，手机端自动把最紧急的阶段排在最前。
- 时间轴头部同样按「并行阶段」展示：单阶段为「当前处于 X · 剩余 …」，多阶段为「当前同时进行 N 个阶段」并逐条列出名称与剩余时间；各阶段卡片、管理端阶段列表的倒计时同样遵守「不足 1 小时转红」。
- 学生端时间轴底部固定「流程与时间如有疑问，请联系实训室管理员或学院教务老师协助处理」。

### 11. 学生端 AI 求职辅助（新增）

**入口**

- 侧边栏新增「AI 助手」分组：**AI 优化简历**、**AI 面试辅导**。
- 「我的简历」页顶部新增「AI 优化简历」卡片；未上传简历时提示先上传，结构化内容仍可手动编辑。
- 「我的志愿」页「AI 面试技巧分析」右上新增「进入模拟演练」；「导师与方向」页右上新增「AI 面试辅导」。

**AI 优化简历**

- **前置条件**：必须先上传 PDF / DOCX 简历。未上传时「开始优化」与「从已上传简历导入」均禁用，页面顶部提示并给「去上传简历」入口；后端 `POST /api/ai/resume-optimize` 直接返回 400。结构化内容仍可手动编辑，但 AI 不分析。
- **范围**：只限制「简历分析 / 改写」链路；AI 面试辅导不依赖简历文件，不受影响。
- 进入页面先加载结构化草稿：个人信息 / 教育背景 / 项目经历 / 实习经历 / 技能描述 / 奖项证书 / 自我评价 / 其他信息。
- 可手动填写，也可点「从已上传简历导入」，后端按常见栏目标题切分 PDF/DOCX 正文并写入草稿（识别不到栏目时整份放入「其他信息」）。
- 右侧设置：目标岗位（可从当前志愿带入）、目标关键词（≤12 个）、四类侧重点（措辞精炼 / 成果量化 / 匹配岗位关键词 / 专业性与可读性）、要优化的栏目。
- 点「开始优化」先自动保存草稿，再调用模型。结果为**原文与建议双栏对照**，附问题、改动理由、关键词覆盖情况。
- 支持单条「应用这条」、单条「应用并编辑」、多选「一键应用全部」；应用后仍可在栏目编辑区继续修改，最后点「保存草稿」。
- 长度约束：单栏 ≤2000 字、总计 ≤8000 字、至少 30 字才可优化；超限时按钮禁用并在下方给出可执行提示。
- 删除简历时同步清空结构化草稿（导入内容与后续编辑一并清除），避免无源内容残留；AI 分析需重新上传。

**AI 面试辅导**

- 三个环节卡片：自我介绍、常见问题演练、岗位相关问题模拟（岗位方向取目标导师研究方向或学生填写的目标岗位）。
- 流程：选择练习设置 → 开始练习（AI 出题）→ 写回答 → 提交 → 反馈；可换题、重答本题、把追问作为下一题继续练。
- 反馈结构：总分 + 等级，结构与逻辑 / 内容充实度 / 表达清晰度 / 岗位匹配度四维评分及依据，做得好的、可以改进、参考表达、追问。
- 最近 10 次练习记录保存在右栏，可打开抽屉回看题目、原回答与完整反馈；记录仅本人可见，不进入导师评分。

**AI 分身会话与真人介入**

- 学生向导师分身提问时，学生问题与 AI 回答都写入 `avatar_messages`；重新打开抽屉可看到历史。
- 学生端气泡标注来源：「AI 分身」为模型生成，「真人老师」为导师本人回复；抽屉打开时每 8 秒轮询，老师新回复自动出现。
- 导师端「我的 AI 分身」页新增「学生咨询」区块：左侧学生列表（最后一条消息、时间、未读数），右侧完整对话与「真人回复」输入框。
- 老师打开会话即把学生消息标记已读；真人回复写入同一线程，并给学生发站内通知。
- 导师端状态卡展示 AI 是否接入（通道 / 模型 / 规则引擎）；未接入时提示管理员在「全局看板 → AI 通道」配置真实模型。
- 权限：学生仅能读自己与某导师的线程；导师仅能读 / 回自己分身的线程。

**异常处理（两个功能一致）**

| 情况 | 页面表现 |
|---|---|
| 离线 / 网络中断 | 页内红色提示「网络不可用 / 连接中断」，草稿与回答保留在页面，恢复后重试 |
| 请求超时 | 提示「服务端可能仍在处理」，草稿 / 回答保留；简历优化超时可先精简内容 |
| AI 额度不足（429） | 红色框「AI 额度不足，已暂停优化 / 练习」，不再弹一次性 toast |
| 内容为空 | 简历：所选栏目为空或不足 30 字时禁用优化并提示；面试：回答不足 10 字禁用提交 |
| 内容超长 | 简历：单栏 >2000 字或总计 >8000 字时标红并禁用；面试：回答 >2000 字禁用提交 |
| AI 返回空结果 | 显示「本次没有可应用的改写建议 / 没有生成反馈」，保留原文与回答，可重试或换题 |

  - 时间轴按原阶段时长重新排：第一个阶段「宣讲」立即生效，后续阶段依次后移，轮次回到第 1 轮；
  - 学生账号、学生档案、简历文件、`resume_drafts`、私信、AI 分身配置保留。
- 重置后：学生可在下次「意向填报」开放时重新选择志愿，导师端不再看到旧面试记录。
- 防回流：`demo.seed.completed` 与 `demo.testdata.version` 标记确保重启后不会把旧志愿/测试场景重新灌回。

### 13. 学生名册（管理端）

- 入口：管理员端「学生名册」，排在「导师与实训室」之前。
- 表格列：学号、姓名、专业、班级、GPA、志愿状态（已填报 / 已录取 / 往轮未录取 / 未填报）、最终去向（含录取轮次）。
- 顶部四个统计卡：学生总数、本轮已填报、已录取、未录取（未填报 / 往轮落选）；支持按学号 / 姓名 / 班级 / 专业关键字过滤。
- 数据源 `GET /api/admin/students`：每人取一条「有效志愿行」——已录取优先，其次当前轮次，最后是最近一轮未录取志愿；因此第 1 轮录取的学生在第 3 轮仍显示「已录取」，不会被当前轮次过滤成「未填报」。
