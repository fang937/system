> 更新时间：2026-11-13（含双选时间轴、简历技能标签、导师详情、调剂人工兜底规则）　分支：bawen

## 一、已实现功能

### 1. 账号与权限
- **四类角色**：学生（STUDENT）、实训讲师（TUTOR）、实训室负责人（LAB_ADMIN）、系统管理员（SYS_ADMIN），共用 `users` 表。
- **三入口登录**：学生端 / 导师端 / 管理员端，账号与入口强绑定，走错入口返回 403；JWT 鉴权。
- **合并工作台**：导师与实训室负责人同走导师端，登录返回 `caps`，负责人多一组「实训室事务」菜单（排期、室内调剂）。
- **职位管理**：管理员可在「导师与实训室」页查看每位成员职位（实训室负责人 / 实训讲师），一键调整：
  - 设为负责人时**自动撤销该室原负责人**（原子换防，无需先手动取消）；
  - 设为讲师时若本人是负责人，清空 `leader_id` 并提示该室进入无负责人状态；
  - 仅系统管理员有权调整，学生 / 导师调用返回 403。

### 2. 双选核心流程（8 阶段）
- `selection_phases` 一张表承载 8 个阶段，时间窗口是唯一权威，所有写接口第一步校验时间，抓包直调同样被拒。
- APPLY / INTERVIEW / CONFIRM 三阶段逐轮重复（round_no 1~3），共 3 轮补录。
- 管理端可「立即进入 / 立即结束」平移窗口，方便演示。
- **意向填报**：学生最多 3 个平行志愿 + 服从实训室内调剂 / 全院调剂两个开关。
- **面试打分**：五维评分标准（专业基础 25% / 实践技能 25% / 学习潜力 20% / 动机匹配 15% / 表达沟通 15%），维度与权重落在 `score_rubrics` 表，前端与 AI 都以它为准。
- **名额并发控制**：`tutors.remaining_quota` + 乐观锁，拟录取用条件 UPDATE 防超卖；第 N+1 人点拟录取会被拒绝。
- **拟录取确认**：单 Offer 自动确认；多 Offer 学生限时选一；超时定时任务释放名额并按递补顺位自动递补。
- **统筹调剂**：三级兜底——实训室内 → 全院 → 人工约谈，按优先级分数从高到低匹配。
  - **不服从调剂的学生不自动分配**：`accept_lab_adjust` 与 `accept_global_adjust` 都为 0 时，自动调剂显式跳过，只计入 `manualPending` 并留在调剂池，等管理员在「人工分配」里约谈指定；管理端表格用「需人工 / 可自动」标签区分，统计卡单独显示「需人工处理」人数。
- **结果公示与导出**：POI 导出录取名单 Excel。

### 3. AI 能力（多通道）
- 三通道：OpenAI / DeepSeek / 通义千问，按优先级尝试，某通道额度耗尽自动切下一个；Key 全空时走内置规则引擎兜底。
- 学生端：面试 tips、实训室推荐（按技能标签 + 名额 + 竞争度）、简历初评。
- 导师端：教师 AI 分身（学生考察期咨询），身份资料与应答边界落在 `ai_personas` 表。
- **教师端 AI 辅助打分**：面试评分弹窗内「AI 简历初评」按五维评分标准（`score_rubrics`）给出各维度建议分 + 依据 + 把握程度，点「采用建议分」预填滑杆；AI 只出建议，最终仍由导师确认保存。

### 4. 简历 OCR 与技能标签
- PDF 优先抽文本层；扫描件调 PaddleOCR / PP-StructureV3 文档解析；DOCX 用 POI 直读段落与表格。
- 抽取结果缓存于 `resume_texts`，重新上传即失效。
- **简历技能标签**（`ResumeTagService`）：按 8 类词表（编程语言 / 后端框架 / 前端技术 / 数据库 / 中间件与部署 / AI 与数据 / 移动端 / 工程能力）从简历正文抽取技术标签。
  - 长词优先且命中区间不重叠，`Spring Boot` 不会同时产出 `Spring`；兼容 `SpringBoot`、`SpringCloud` 这类无空格写法。
  - 学生端「我的简历」上传后直接显示标签云与正文字数；教师端「AI 简历初评」在摘要下方展示同一套标签（`resumeTags`），不依赖大模型，模型不可用时照样出标签。

### 5. 实训室信息展示
- `labs` 表除核心方向外，承载 8 个实训室级横向对比字段：后端/工程技术栈、前端/客户端技术栈、AI/大模型方向、项目产出类型、竞赛/科研成果、培养模式、考核/结业标准、适合人群。
- 学生端导师页顶部「实训室概览」卡片组，可展开每室详情；管理端实训室编辑弹窗可改这 8 项。
- 真实名册幂等种子 `backend/src/main/resources/db/labs-tutors-seed.sql`，每次启动自动对齐，不重置已消耗名额、不改导师密码。

### 6. 其他
- 站内通知（Offer / 超时 / 结果）、操作日志、面试排期、学生档案与简历管理。
- 容器化：`docker-compose.yml`（mysql + backend + frontend/nginx），配置全部走 `.env`。

### 7. 师生直连私信
- 学生可在任意导师卡片打开抽屉，在「AI 分身」之外切换「直接留言」，**与全部 25 位导师真实对话**；导师端「学生留言」页统一收发，带未读红点。
- 私信页左侧为微信式两级选择：**最近会话** + **按实训室找老师**。先选实训室（手风琴，一次只展开一个），再点该室具体老师；未聊过的老师也能直接发起会话，对话区给「还没有和 XX 老师聊过」占位提示。
- 新表 `direct_messages`，与 `notifications` 分工：通知是系统单向广播，私信是双向会话 + 已读语义。
- 发送者永远取自登录身份（请求体不接受 senderId，杜绝冒名）；仅学生 ↔ 导师/负责人互通，学生↔学生、导师↔导师、自发均返回 400。

### 8. 双选时间轴（三端同步）
- 组件 `SelectionTimeline`，数据源为 `/api/meta/phase` 返回的 `phases`，与 `selection_phases` 同源，管理端改时间后三端立即一致。
- 8 步文案按学院流程图落地：集中宣讲 → 实训室开放日 → 意向填报 → 导师初选与面试考核 → 拟录取与学生确认 → 分轮补录 → 统筹调剂录取 → 结果公示与正式入组。
- 三个使用位置：
  - **管理端「阶段与轮次」**：完整版，每步带说明文字与倒计时，配合下方列表改时间 / 立即进入 / 立即结束；
  - **学生端「导师与方向」「我的志愿」**：紧凑版，8 步常显、说明可展开，填报窗口关闭后学生一眼看到已截止；
  - **教师端「报考我的学生」**：紧凑版，与管理员端同一份数据。
- 顶栏常驻「当前阶段」徽章：进行中为绿青渐变实色底 + 呼吸圆点 + 剩余时间胶囊，未开始橙色，无进行中阶段灰色。
- 学生端时间轴底部固定「流程与时间如有疑问，请联系实训室管理员或学院教务老师协助处理」。

### 9. 导师详情与展示口径
- 学生端导师卡片整卡可点开右侧详情抽屉：技能标签（按「、」拆分 `research_direction`）、完整介绍、预计招收名额、所属实训室与室方向，底部一键「问 AI 分身」或「去填报志愿」。
- 卡片内的 AI 分身按钮使用 `@click.stop`，点它不会误触详情抽屉。
- 学生端名额口径统一为「预计招收 N 名」，**不再展示报考人数与竞争度进度条**；管理端仍保留「已用/总数」的管理视角。

### 10. 响应式自适应
- 全局 1100 / 900 / 700 / 560 / 360 五档断点；900px 以下侧边栏收为抽屉，表格容器 `min-width:0` 允许内部横向滚动，操作列固定右侧不丢失。

## 三、技术栈

- 后端：Spring Boot 3.5.6 + MyBatis-Plus 3.5.16 + MySQL 8 + JWT + POI
- 前端：Vue 3.5 + Element Plus 2.14 + Pinia + Vite 5
- 中间件（PRD 规划，部分未接）：Redis 限流、RabbitMQ 通知、Quartz 定时任务（当前用 Spring `@Scheduled`）

## 四、启动

```bash
# 后端（本地）
cd backend && mvn spring-boot:run
# 或 java -jar target/lab-select.jar（需注入 DB_HOST/DB_PASSWORD 等环境变量）

# 前端
cd frontend && npm install && npm run dev -- --port 8089
```

详见 `docs/启动指南.md`。演示账号密码统一 `123456`。
